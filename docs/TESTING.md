## 公开版软件检查

`python3 tools/test.py` 直接编译生产状态与绘图代码，检查：

- 电池/旁路状态优先级、可信通知来源过滤。
- 4,848 个竖屏与 4,545 个横屏采样帧：391 点尺寸、亮度、裁切范围、电池轮廓、数字稳定和完成后停帧。
- 方向确认、边界抖动、平放退出、息屏恢复和 200 次交替方向。
- 360 个整组旋转采样帧：图标、数字和百分号共同变换，终点一致、快速反向衔接和安全区域。
- 首次引导、开关保留、后台确认记录、可选通知策略。
- 连续传感器样本的有效期、重连节流和紧凑排版回退。
- 3,636 个锁屏方向补偿案例：三个系统固定方向、三个阅读方向、0–100% 电量及四种状态；核对实际面板坐标、完整数字和紧凑排版。另检查熄屏/亮屏交接、锁屏过渡裁切与 CPU 唤醒条件。

正式 APK 核对应用名、包名、版本与签名；证书摘要与内部版一致。新包名的权限独立，不沿用内部版授权结果。

## 公开包名的短时真机检查

公开包名的先行构建已在 PZ261A 安装运行：USB 供电、真实 100% / FULL，服务提交 391 点画面，后台未受限、电池优化豁免与恢复任务有效，接口错误为 0。

锁屏、背屏朝上的 45 秒检查中，30 次采样均为系统背屏开启、391 点自定义画面、接口错误 0；用户确认可见“电池＋对勾＋100%”。背屏朝下时可进入系统姿态门控，不能据此判断应用退出。

锁屏旋转修复已覆盖安装到正式签名的 1.0.0，安装文件与本机构建的 SHA-256 一致。用户确认锁屏下左右旋转正常；记录显示系统方向冻结为 0° 时，应用仍完成两个横屏与竖屏切换，整组过渡约 180 ms。后续亮屏方向重新对齐，CPU 保持在锁屏可见姿态启用，亮屏和背屏朝下时释放，接口错误 0。该轮是短时检查，不代表长时间待机结果。

另复现抬起亮屏时短暂显示 Amoo/系统图案。对应记录中，人脸识别使用前置相机，固件切入 `scene_camera_preview` 的 SPECIAL 层，约 0.9 秒后自动交还应用画面。工具箱不能覆盖这种更高优先级场景；完整相机拍摄、来电场景仍待验证。

## 内部版已有的真机结果

这些说明实现的验证来源，**不能当作公开包名下重新完成的验收**。

| 场景 | 范围 |
| --- | --- |
| USB 供电、100% / FULL | 391 点画面提交，用户确认竖屏实物可见 |
| 左右横屏 | 完成布局与整组过渡调整；最后一轮记录覆盖 40 次系统方向变更，用户反馈改善 |

| 开关与最近任务 | 关闭后交还帧并取消任务；重新开启恢复；移除设置页面不主动停止服务 |
| 关闭可选权限 | 1.4.1 主包在通知权限拒绝、旁路监听关闭时，普通显示、模拟崩溃恢复与强制派发恢复任务通过 |

软件方向轨迹、应用耗时和系统帧提交成功不等于硬件可见延迟。强制派发恢复任务不代表自然调度等待时间，模拟崩溃不代表真实低内存压力。
