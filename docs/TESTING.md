## 1.1.0 听见

早期方形包络版本的纯 Java 检查覆盖中央 17×17 边界、3,600 个阅读方向与系统锚点投影、静音、直流偏置、六通道与反相输入的振幅计算、三档灵敏度、停止/静音衰减，以及新场景优先级。这些历史检查只使用合成信号；当前竖屏版本的范围见本节末尾。

PZ261A 当前固件的应用内只读查询上报 `built_in_mic` 与 `back_mic` 两组位置，输入声道数为 `[1, 2]`；厂商麦克风描述文件的动态映射为 PROCESSED。快速输入 profile 声明六声道格式不能证明六路独立原始麦克风已向应用开放。实际开始时分别尝试六声道位置与索引格式，核对服务端格式及活动麦克风的独立 DIRECT 映射，未核实则退回单／双声道。真实采集和锁屏停止检查需要用户授权麦克风，不能用合成预览替代。

正式签名主包的真实采集检查确认：六声道位置格式不可用；六声道索引格式虽然建立了客户端 6 声道，服务端实际仍为 2 声道，活动映射只有 `built_in_mic:0=processed`。应用自动回退到普通 MIC 双声道、48 kHz，不提供声源方位。此结论限于本轮已测试的固件和应用公开接口，不能推断设备仅有两颗物理麦克风。

原始输入路径存在读取迟缓，正常采集改用 MIC 和较小缓冲；路由、静音与麦克风映射查询移至独立线程。最终 20 秒短测约每秒读取 40 个 25 ms 音频块，计算耗时在采样中小于 1 ms，系统未将客户端静音；20 秒后主动停止，AppOps 录音占用结束、CPU 采集锁释放，返回真实满电显示。该轮采样期间主屏一直亮着，没有把它计作锁屏实物验收。用户随后确认波形已能正常随声音变化，同时指出容易触顶、画面不美观；这项反馈不等同于完整锁屏方向验收。

随后按 [点阵视觉设计基线](VISUAL_DESIGN.md) 重绘“听见”：七根间隔细线、四周留白、有限亮度阶梯，以及三档软压缩增益。纯 Java 检查区分弱输入、说话级、强输入与接近满幅的合成振幅，验证三档均保留变化，满幅输入保留端点余量；同时检查静音停帧、无效值、循环接缝、留白与 3,600 个方向投影。完整循环与关键帧由生产代码导出并审看。

七根细线版的正式签名 1.1.0 已覆盖安装，手机安装文件与本机构建的 SHA-256 一致。手机端合成预览提交 391 点，实际输出符合七根细线与安全边界，接口错误为 0；覆盖安装及预览没有自动启动麦克风，结束后返回真实充电显示。用户随后确认能听见，但仍不认可波形观感，要求只考虑竖屏并增加真实变化细节；不能把这一反馈记作视觉验收通过。
